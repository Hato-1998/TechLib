    6과 · 협업·도구 제작과 출시 후 변경¶

    퀘스트를 열 개 더 만들 때마다 프로그래머가 조건 분기를 추가해야 한다면 다음 업데이트가 늦어집니다. 디자이너가 직접 바꿀 값, 코드에서 보장할 규칙, 기존 저장 파일에 미칠 영향을 한꺼번에 살펴보세요.

    콘텐츠 하나를 다음 담당자에게 넘기기¶

    퀘스트 정의에 ID, 선행 퀘스트 ID, 목표 수, 보상 ID를 둡니다. 편집 도구는 중복 ID, 없는 보상, 0 이하 목표, 선행 조건의 순환을 찾아 문제 항목과 이유를 표시합니다. 첫 퀘스트는 프로그래머가 만들고 두 번째는 동료가 안내만 보고 추가해 보게 합니다. 어떤 단계에서 질문이 나왔는지가 도구와 문서의 다음 수정 대상입니다.

    출시 후 변경 문제　패치로 퀘스트 이름과 목표 수가 바뀌었습니다. 표시 이름을 저장 키로 썼다면 예전 진행도를 찾지 못할 수 있습니다. 안정적인 ID와 저장 버전을 사용하고, 이미 완료한 퀘스트·진행 중인 퀘스트·처음 받는 퀘스트의 변환 규칙을 각각 적습니다. 패치 전 저장 파일 사본으로 읽기와 재저장을 시험합니다. 결측값과 실제 0도 구분하세요.

    협업 과제　기획에는 진행 중인 목표를 소급 변경할지 묻고, QA에는 재현 저장 파일과 기대 결과를 전달합니다. 리뷰어에게는 수정 범위·선택한 대안·실패 시 복구 경로를 남깁니다. AI가 만든 수정안도 동일한 이전 버전 데이터와 경계 입력으로 검증합니다. 코드 작성자를 바꿔도 판정 기준은 같습니다.

    완료 기준　두 번째 콘텐츠 추가 예시, 잘못된 데이터의 진단 메시지, 예전 저장 파일 검증 결과, 다른 사람이 따라 할 수 있는 짧은 인계문을 제출합니다.
