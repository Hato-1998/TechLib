# 4과 · 입력·화면과 플레이 감각

리듬 게임에서 플레이어는 박자에 맞춰 눌렀는데 판정은 한 프레임 늦게 표시됩니다. 입력을 받은 시각, 곡의 재생 시각, 판정을 계산한 시각, 결과를 그린 시각을 나눠 살피세요. 화면이 늦게 그려진 것이 판정 자체가 틀렸다는 증거는 아닙니다.

## 조작감을 규칙으로 표현하기

플랫포머에서 착지 직전 입력한 점프를 받아 주려면 입력을 잠시 보관하는 버퍼가 필요합니다. 얼마나 오래 보관할지, 착지 때 한 번 소비한 입력을 다시 쓸 수 있는지, 메뉴에서 누른 버튼도 후보에 들어가는지 정합니다. 시간 수치는 튜닝할 수 있게 두고, 창 안쪽·경계·바깥쪽 입력을 시험합니다.

**UI 실습**　전략 게임의 생산 목록에서 키보드로 항목을 고른 뒤 패드로 상세 창을 닫습니다. 목록이 정렬됐거나 항목이 사라졌을 때 포커스를 어디로 돌릴지 정하세요. 항목의 안정적인 ID를 기억하면 화면상의 줄 번호가 바뀌어도 같은 대상을 찾을 수 있습니다. 대상이 사라졌다면 조작 가능한 이웃 항목을 선택합니다.

**플레이테스트**　두 가지 점프 입력 허용 시간을 같은 구간에서 비교합니다. 시도 수, 성공 수, 의도하지 않은 재점프와 플레이어의 말을 함께 기록하세요. 성공률만 높아져도 조작이 둔하게 느껴질 수 있습니다. 기획자에게는 느낀 차이를, 코드 리뷰에는 판정 근거와 재현 입력을 전달합니다.

**완료 기준**　입력 기록 하나로 규칙 오류와 표시 지연을 구분하고, 포커스 복귀와 장치 전환을 실제 조작으로 확인합니다.
