# 5과 · 디버깅·성능 측정과 회귀 테스트

도시 시뮬레이션에서 주민이 많아지자 카메라를 움직일 때 끊깁니다. 주민 AI, 보이는 건물의 렌더링, 새 구역 스트리밍 모두 후보입니다. 같은 저장 파일과 카메라 경로를 반복하고, 각 가설이 맞다면 어떤 구간의 시간이 늘어날지 먼저 적습니다.

## 숫자를 읽는 연습

가상의 측정 결과에서 AI가 5ms에서 2ms로 줄었는데 GPU는 여전히 20ms입니다. AI 최적화의 효과는 CPU 구간에서 확인할 수 있습니다. 화면의 프레임 시간이 얼마나 줄었는지는 GPU와 대기가 포함된 전체 기록을 봐야 합니다. 평균이 좋아져도 처음 구역을 열 때 한 번 생기는 100ms 끊김은 남을 수 있습니다. 첫 진입과 반복 진입을 나눠 보세요.

**회귀 문제**　인벤토리를 세 번 열면 아이템 하나가 세 줄로 표시됩니다. 저장된 아이템 수, 모델 통지 횟수, 위젯 콜백 횟수를 같은 ID로 기록합니다. 값이 1·1·3이라면 세 번째 단계에서 중복 등록과 여러 위젯 인스턴스를 조사합니다. 처음부터 저장 코드를 고치면 관찰된 원인을 놓칩니다.

**실습**　최소 재현 절차 → 실패하는 검사 → 수정 → 동일 검사 재실행을 한 묶음으로 남깁니다. 순수 계산은 단위 테스트, 위젯 수명은 통합 테스트, 플랫폼·로딩·입력 차이는 패키지 빌드에서 확인합니다. 재현율이 낮은 문제는 한 번 성공한 결과와 반복 검증 결과를 구별하세요.

**완료 기준**　수정 전후의 동일 조건 측정표와 회귀 검사 한 건을 남깁니다. 수치가 개선되지 않았으면 기각한 가설과 다음 측정 위치를 설명합니다.
