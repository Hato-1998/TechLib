# 4과 · 성능 측정과 오류 추적

적 1,000마리가 플레이어 네 명과의 거리를 매 프레임 검사합니다. 거리 계산을 절반으로 줄였는데 프레임 시간이 그대로라면, 다음에는 무엇을 측정할까요?

## 증상에서 측정 지점 고르기

거리 계산은 프레임마다 4,000번입니다. 하지만 시야 검사나 GPU가 더 오래 걸릴 수 있습니다. 같은 장면에서 각 작업의 시간과 최종 프레임 시간을 따로 비교하세요. 화면 버그에서도 같은 방식으로 최초로 기대와 달라진 지점을 찾습니다.

## 읽고 풀기

1. [C++ 문제집](stage1/index.html#01-cpp-basics)의 메모리 배치·캐시와 자료구조 절을 읽고 [공간 분할](../01-data-structures/index.md), [캐시 메모리](../03-cache-memory/index.md)를 연결합니다.
2. [적 1,000마리 비용 계산](UE5_Content_Programming_Workbook.md#4-1000)과 [프로파일링 도구](../10-profiling/index.md)를 읽습니다. 동일한 카메라·빌드·적 수에서 평균과 느린 프레임을 비교할 방법을 정합니다.
3. [중복 콜백 디버깅](UE5_Content_Programming_Workbook.md#10-ai)을 읽고 [종합 평가](UE5_Content_Programming_Workbook.md#ide)를 풉니다. [시니어 지식](../senior-knowledge/index.md)의 코드 리뷰 항목과 함께 자신의 수정 근거를 설명해 보세요.

**확인 문제**　서버 지급 1회, 상태 통지 1회, UI 콜백 3회라면 어디에 중단점을 둘까요?

**풀이**　위젯의 알림 등록과 해제에 두고 인스턴스와 등록 횟수를 확인합니다. 수정 뒤에는 같은 창을 세 번 열었다 닫고 상태를 한 번 바꿔 콜백 횟수를 다시 셉니다.
