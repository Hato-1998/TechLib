# 3과 · 게임 규칙과 데이터 설계

턴제 카드 게임에서 독 피해와 회복이 같은 턴에 예약됩니다. 체력 2인 캐릭터에게 피해 3, 회복 2를 적용하면 순서에 따라 생존 여부가 달라질 수 있습니다. 먼저 기획자와 “사망은 각 효과 직후 판정하는가, 턴이 끝날 때 판정하는가?”를 합의하세요. 그 답이 처리 순서와 테스트의 기대값이 됩니다.

## 규칙을 재현할 수 있게 만들기

카드 정의에는 비용과 효과 종류를 두고, 이번 경기 상태에는 소유자·현재 체력·예약된 효과를 둡니다. 같은 우선순위의 효과에는 생성 순번처럼 명시적인 순서를 부여합니다. 난수가 판정을 바꾼다면 입력과 시드뿐 아니라 처리 순서와 규칙 버전도 기록합니다. 시드 하나만 같아도 난수를 꺼내 쓰는 순서가 다르면 결과가 달라집니다.

**설계 문제**　같은 카드 사용 요청이 두 번 도착했습니다. 사용한 카드 종류만 보고 중복을 거르면 같은 카드를 정당하게 두 번 쓰는 플레이까지 막습니다. 한 행동의 식별자와 현재 턴을 검증하고, 처리된 요청의 결과를 재사용할 범위를 정하세요. 싱글플레이에서는 실행 취소와 저장 복원이, 온라인에서는 서버 권한과 재전송이 같은 설계를 다른 방향에서 시험합니다.

**다른 장르로 옮겨 보기**　건설 게임에서 건물을 철거한 뒤 옛 저장 파일을 불러옵니다. 건물 정의, 배치 인스턴스, 화면 표시 중 무엇을 저장해야 할까요? 새 버전에서 생산 시간이 바뀌면 진행 중인 건물에 언제 적용할지도 정합니다.

**완료 기준**　정상·중복·경계·복원 입력을 포함하는 상태 전이표를 작성하고, 그 표의 세 행 이상을 UI 없이 테스트합니다.
