# 1과 · 낯선 코드 읽기와 객체 수명

새 팀에서 처음 받은 버그는 “파티원을 교체하면 이전 캐릭터의 버프 아이콘이 남는다”입니다. 먼저 디버거로 교체 입력부터 화면 갱신까지 따라가 보세요. 입력을 받은 객체, 파티 구성을 바꾼 객체, 알림을 보낸 객체, 화면을 그린 객체를 호출 순서대로 적습니다. 같은 객체가 여러 역할을 맡아도 괜찮습니다. 실제 코드에서 관찰한 경로가 출발점입니다.

## 무엇이 언제까지 살아야 할까?

캐릭터 한 명의 버프는 캐릭터와 함께 사라질 수 있습니다. 파티 편성과 계정 업적은 더 오래 남습니다. C++의 RAII는 객체의 수명에 자원 반납을 묶는 방법이고, 언리얼의 GC는 도달 가능한 UObject를 추적합니다. 둘 중 어느 것도 “현재 선택된 캐릭터가 누구인가”를 대신 판정하지 않습니다. 포인터가 유효해도 이미 교체된 대상일 수 있습니다.

**코드 읽기 문제**　동료 목록을 순회하면서 탈퇴한 동료를 같은 배열에서 제거합니다. 다음 동료를 건너뛰거나, 재할당 뒤 낡은 주소를 읽을 수 있는 위치를 표시하세요. 제거가 순서를 보존해야 하는지에 따라 역순 제거, 제거 대상 수집, 조건 기반 일괄 제거 중 하나를 선택하고 이유를 적습니다.

**다른 장르로 옮겨 보기**　퍼즐 게임에서 실행 취소로 삭제된 블록이 복원됩니다. 과거 블록 주소를 저장했을 때와 안정적인 ID와 복원 데이터를 저장했을 때의 차이를 설명하세요.

**완료 기준**　본인이 작성하지 않은 기능 하나의 호출 경로를 파일·함수 단위로 기록하고, 대상 교체 전후에 끊어야 하는 참조나 구독 한 개를 디버거에서 확인합니다.
