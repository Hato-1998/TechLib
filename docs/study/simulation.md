# 2과 · 시간·공간과 게임플레이 구현

플랫포머에서 캐릭터가 초당 6m를 달립니다. 매 프레임 0.1m를 이동시키면 60fps에서는 의도한 속도가 나오지만 30fps에서는 3m/s가 됩니다. 속도와 프레임당 이동량을 구별하는 일부터 시작합니다.


아래는 충돌이 없는 등속 직선 이동만 다루는 C++ 예제입니다.


```cpp
float Advance(float positionM, float speedMps, float deltaSeconds)
{
    return positionM + speedMps * deltaSeconds;
}
```

1초를 30번과 120번으로 나눠 각각 계산하면 두 결과는 부동소수점 오차 범위 안에서 같습니다. 하지만 이 결과만으로 점프·충돌·마찰까지 프레임률에 독립적이라고 할 수는 없습니다. 충돌을 이동 끝점에서만 확인하면 긴 프레임 동안 얇은 벽을 통과할 수 있습니다. 이동 경로를 쓸어 검사하는 방법과 작은 고정 시간 간격으로 나누는 방법의 비용을 비교하세요.

**공간 문제**　레이싱 게임에서 차량의 전방 벡터와 다음 체크포인트까지의 방향을 같은 좌표계에서 정규화해 내적합니다. 값이 음수이면 체크포인트는 차량 뒤쪽에 있습니다. 위치가 정확히 같아 방향을 정할 수 없는 경우도 처리하세요. AI가 다음 지점을 자꾸 바꾼다면 경계 근처의 입력과 전환 조건을 기록합니다.

**실습**　30·60·120fps와 중간에 긴 프레임이 한 번 끼는 조건에서 이동 거리, 벽 통과 여부, 착지 프레임을 기록합니다. 점프가 어색할 때는 궤적과 애니메이션 전환을 따로 관찰하세요. 발이 미끄러지면 실제 이동 속도와 걷기 애니메이션의 재생 속도를 먼저 비교합니다.

**완료 기준**　문제를 재현하는 입력 시퀀스, 기대한 궤적, 실제 궤적을 남기고 수정이 유효한 조건을 설명합니다.
